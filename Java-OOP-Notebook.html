INTRODUCTION TO OOP

🎬 OOP 1

✦ WHY OOP? ✦

🧠 IDEA

The real world is made of things — students, cars, bank accounts. Each thing has data (name, balance) and does work (greet, withdraw). Object-Oriented Programming lets code copy that shape: bundle data + behaviour into one unit called an object.

❓ WHY DO WE NEED IT? — feel the problem first

Store roll no, name and marks of 5 students:

😩 without OOP
int[]    rno   = new int[5];
String[] name  = new String[5];
float[]  marks = new float[5];
// student #3 = rno[2] + name[2] + marks[2]   ← scattered in 3 arrays!
  • one student's data lives in 3 different places
  • add "phone no." → change every array and every loop
  • nothing stops index mix-ups between arrays
  • where does greeting() belong? to whom?
😍 with OOP
class Student {            // ONE new data type that groups everything
    int rno;
    String name;
    float marks;
}

Student[] students = new Student[5];   // 5 students, ONE array
💡 CORE IDEA

A class lets you create your own data type. int stores one number — Student stores a whole student.

🌍 IN REAL LIFE

Procedural code = a recipe: step 1, step 2, step 3. OOP = a restaurant: chef, waiter, cashier — each one knows its own data and its own job, and they work by talking to each other.

PROCEDURAL OBJECT-ORIENTED
Thinks in steps / functions objects (data + behaviour)
Data separate, often global inside objects, can be hidden
Reuse copy functions around inheritance, composition
Safety anyone can change any data access control (private …)
Large projects gets tangled fast maps the real world, scales
Examples C Java, C#, C++ (C++ & Python are multi-paradigm)
☕ JAVA REALITY

Java is not "100 % pure" OOP — primitives (int, char, …) are not objects and static members exist without any object. It's a deliberate speed/convenience trade-off.

Ch 01 · Class & Object

✦ CLASS & OBJECT ✦

🧠 IDEA

Class = blueprint / template. Object = the actual thing built from it — an instance of the class.

          CLASS = blueprint                     OBJECTS = real things
   ┌───────────────────────────┐          ┌─────────────┐  ┌─────────────┐
   │  class Student            │          │ rno   = 15  │  │ rno   = 18  │
   │    ─ rno                  │   new    │ name  =Kunal│  │ name  =Rahul│
   │    ─ name                 │ ───────→ │ marks = 85.4│  │ marks = 90.3│
   │    ─ marks                │          └─────────────┘  └─────────────┘
   │    ─ greeting()           │               kunal            rahul
   └───────────────────────────┘
       logical (just a plan)              physical (occupy memory in heap)

finding classes in a problem:
nouns → classes
verbs → methods

🌍 IN REAL LIFE

An architect's house plan → you can't sleep in a plan, but you can build 100 houses from it. Every house follows the same plan, yet each can have its own paint colour (its own state).

📖 DEFINITION
  • Class — a named group of properties (fields) and functions (methods). It creates a new data type.
  • Object — an instance of a class. Exists at runtime, occupies memory.
  • Instance variable (field) — declared inside the class, outside methods. Every object gets its own copy.
  • Method — a function inside a class; the object's behaviour.

✍️ SYNTAX

Java
class ClassName {
    // fields   → state
    // methods  → behaviour
}

ClassName ref = new ClassName();   // create an object
ref.field;                         // dot operator → reach into that object
ref.method();

💻 EXAMPLE 1

Main.java
public class Main {
    public static void main(String[] args) {
        Student kunal = new Student();
        kunal.rno = 15;
        kunal.name = "Kunal";
        kunal.greeting();

        Student rahul = new Student();       // never touched
        System.out.println(rahul.name + " " + rahul.rno
                           + " " + rahul.marks);
    }
}

class Student {
    int rno;
    String name;
    float marks = 90;      // explicit initial value

    void greeting() {
        System.out.println("Hello! My name is " + name);
    }
}
▶ Output
Hello! My name is Kunal
null 0 90.0

🔎 WHAT JUST HAPPENED?

  1. new Student() → a fresh object in the heap; every field gets a default value (unless initialised, like marks = 90).
  2. kunal.rno = 15 → the dot operator reaches kunal's copy of rno.
  3. rahul is a different object → null 0 90.0.
field type default value
byte short int long 0
float double 0.0
char '\u0000'
boolean false
any reference (String, arrays, objects) null

🧠 VISUALIZE IT — 3 properties of every object

                          an OBJECT
           ┌──────────────────┼──────────────────┐
           ↓                  ↓                  ↓
         STATE             IDENTITY           BEHAVIOUR
     values of its       which object is     what it can do
     fields right now    it? (its own place   = its methods
     name = "Kunal"       in memory)          greeting()
⚠️ COMMON MISTAKE

Student kunal; creates no object — only an empty reference variable. Use a local one before assigning → ✗ compile error. A field left like that is null → NullPointerException when you use it.

Ch 01 · References, new & memory

✦ REFERENCES, new & MEMORY ✦

🧠 IDEA

new creates the object in the heap at runtime and returns a reference to it — think of it as an arrow / address-like handle. The variable stores only that arrow, never the object itself.

Java
Student s;            // ① declare a reference — no object yet
s = new Student();    // ② create object in heap, store its reference in s
   ① Student s;                         ② s = new Student();

     STACK             HEAP               STACK             HEAP
   ┌─────────┐                          ┌─────────┐      ┌───────────────┐
   │ s : ?   │      (nothing)           │ s : ●───┼────→ │ Student obj   │
   └─────────┘                          └─────────┘      │ rno   = 0     │
                                                         │ name  = null  │
                                                         │ marks = 90.0  │
                                                         └───────────────┘

🧠 Who looks at which side?

        Student  s  =  new Student();
        └──┬──┘        └─────┬─────┘
           ↓                 ↓
     LEFT side:          RIGHT side:
     the COMPILER        the JVM at RUNTIME
     checks the type     creates the object
     (what you may call) (dynamic memory allocation)

💻 Two references, ONE object

Main.java
public class Main {
    public static void main(String[] args) {
        Student one = new Student();
        Student two = one;           // copies the ARROW, not the object
        one.name = "Something something";
        System.out.println(two.name);
    }
}

class Student { String name; }
▶ Output
Something something
     one ──────┐
               ↓
       ┌─────────────────────────────────┐
       │ Student { name = "Something…" } │   ← ONE object in heap
       └─────────────────────────────────┘
               ↑
     two ──────┘

❓ Why no new for int?

Primitives are not objects — the variable holds the value itself. No heap trip → fast.

      int a = 10;                     Student s = new Student();
      STACK                           STACK             HEAP
    ┌──────────┐                    ┌─────────┐      ┌──────────┐
    │  a = 10  │ ← the value        │ s : ●───┼────→ │  object  │
    └──────────┘                    └─────────┘      └──────────┘
☕ JAVA REALITY

"Locals on the stack, objects on the heap" is the right mental model. Fields — even int fields — live inside their object on the heap, and the JIT may optimise allocations away. A Java reference is not a pointer you can do maths on — no pointer arithmetic is part of what makes Java safe.

🎯 INTERVIEW TRAP

Student b = a; does not copy the object — it copies the reference. Both names now control the same object. (Real copying = cloning, Ch 06.)

🌍 IN REAL LIFE — remote & TV

The remote is the reference; the TV is the object. Two remotes can control one TV. A remote can be paired to nothing (null). Lose every remote → nobody can reach that TV → it's garbage.

Saying "s is a Student object". Better: "s refers to a Student object." Getting this sentence right fixes half of all OOP confusion.

Ch 01 · Constructors

✦ CONSTRUCTORS ✦

❓ WHY?

Filling fields one by one (kunal.rno = 15; kunal.name = …) is boring and easy to forget. We want to create + initialise in one line:

Java
Student kunal = new Student(15, "Kunal Kushwaha", 85.4f);

🌍 IN REAL LIFE

When a house is built, electricity, paint and keys are set up exactly once, at construction time — before anyone moves in.

📖 DEFINITION

A constructor is a special block that runs automatically when an object is created with new, before new hands back the reference. It has the same name as the class and no return type — not even void.

⭐ JAVA RULE
  • No constructor written → compiler adds a default no-arg constructor.
  • You write any constructor → the default one is not added.
  • void Student() { } is not a constructor — it's an ordinary method that happens to share the class name!

💻 EXAMPLE — all 3 kinds (the class example)

Main.java
public class Main {
    public static void main(String[] args) {
        Student kunal  = new Student(15, "Kunal Kushwaha", 85.4f);
        Student random = new Student(kunal);   // copy-style
        Student def    = new Student();        // no-arg
        System.out.println(kunal.name + " | " + random.name);
        System.out.println(def.name + " " + def.marks);
    }
}

class Student {
    int rno; String name; float marks = 90;

    Student() {                                    // ① no-arg
        this(13, "default person", 100.0f);        //    → delegates to ③
    }
    Student(Student other) {                       // ② takes another object
        this.rno = other.rno;
        this.name = other.name;
        this.marks = other.marks;
    }
    Student(int rno, String name, float marks) {   // ③ parameterized
        this.rno = rno; this.name = name; this.marks = marks;
    }
}
▶ Output
Kunal Kushwaha | Kunal Kushwaha
default person 100.0

Three constructors, same name, different parameters → constructor overloading. Java picks the one whose parameters match the arguments.

⚠️ The disappearing default constructor

Box.java
class Box {
    int l;
    Box(int l) { this.l = l; }
}

class Test {
    void make() {
        Box b = new Box();     // ✗ no Box() exists any more
    }
}
💥 compile error
error: constructor Box in class Box cannot be applied to given types;
  required: int
  found:    no arguments
CONSTRUCTOR METHOD
Name same as class anything
Return type none (not even void) must have one (void counts)
Called automatically by new, once per object explicitly, any number of times
Inherited? ✗ never ✓ (non-private)
Can be static / final / abstract? ✗ ✓
🎯 INTERVIEW TRAP

"Constructors return nothing, so new returns nothing?" ✗ — the constructor has no return type, but the new expression evaluates to the reference of the new object.

Ch 01 · this

✦ THE this KEYWORD ✦

🧠 IDEA

this = a reference to the current object — the object on which the method or constructor is running right now.

the classic use
class Student {
    String name;

    Student(String name) {
        this.name = name;
             ↑      ↑
             │      └── the PARAMETER (local variable)
             └── the FIELD of the current object
    }
}
⚠️ COMMON MISTAKE

name = name; assigns the parameter to itself (the local variable shadows the field). The field stays null. Use this.name = name;.

🧠 VISUALIZE IT — this changes with the caller

   kunal.greeting();   →   inside greeting():  this == kunal
   rahul.greeting();   →   inside greeting():  this == rahul

     kunal ───→ ┌──────────────┐ ←─── this
                │ name = Kunal │      (while kunal.greeting() runs)
                └──────────────┘

✍️ 4 uses of this

  1. this.field — separate a field from a same-named parameter
  2. this(...) — call another constructor of the same class (constructor chaining)
  3. obj.compare(this) — pass the current object as an argument
  4. return this; — return the current object → calls can be chained: acc.deposit(10).deposit(20)

💻 CONSTRUCTOR CHAINING

   new Student()
        │
        ↓   this(13, "default person", 100.0f)
   Student(int, String, float)      ← the real work is written ONCE here
        │
        ↓
   object ready: rno = 13, name = "default person", marks = 100.0
⭐ JAVA RULE

this(...) (and super(...), Ch 03) must be the first statement of a constructor — and a constructor can't call both.

☕ JAVA REALITY

Since Java 25 ("flexible constructor bodies") you may write statements before this(...)/super(...) — e.g. argument checks — as long as they don't use the object being built. Exams and most codebases still follow the classic "first statement" rule.

🎯 INTERVIEW TRAP

this cannot appear in a static method — a static method runs without any current object (Ch 02).

Ch 01 · Wrapper classes

✦ WRAPPER CLASSES ✦

🧠 IDEA

Every primitive has an object version in java.lang:

primitive byte short int long float double char boolean
wrapper Byte Short Integer Long Float Double Character Boolean

❓ WHY?

  • collections & generics hold objects only → ArrayList<int> ✗ · ArrayList<Integer> ✓
  • a wrapper can be null ("no value yet")
  • handy helpers: Integer.parseInt("42"), Integer.MAX_VALUE, Character.isDigit(c)
Java
Integer num = 45;   // autoboxing:  int → Integer   (Integer.valueOf(45))
int n = num;        // unboxing:    Integer → int   (num.intValue())

💻 The swap puzzle

WrapperExample.java
public class WrapperExample {
    public static void main(String[] args) {
        Integer a = 10, b = 20;
        swap(a, b);
        System.out.println(a + " " + b);
    }

    static void swap(Integer a, Integer b) {
        Integer temp = a;
        a = b;
        b = temp;
    }
}
▶ Output
10 20

🔎 WHAT JUST HAPPENED?

Java is always pass-by-value. For objects, the value that gets copied is the reference. swap() shuffles its own copies of the arrows; main's a and b never move. (And Integer is immutable, so the 10-object can't turn into 20 either.)

      main()                               swap()
      a ───→  10  ←─────────────────────── a'  ┐  swap() re-points only
      b ───→  20  ←─────────────────────── b'  ┘  its own copies a', b'
Integer cache

Integer x = 127, y = 127; → x == y is true (values −128…127 are cached). Integer p = 128, q = 128; → p == q is false (two different objects). Compare wrappers with .equals(), never ==.

⚠️ COMMON MISTAKE

Integer v = null; int k = v; → unboxing null throws NullPointerException.

Ch 01 · final

✦ THE final KEYWORD ✦

🧠 IDEA

final = assign once, never re-assign.

  • final variable → a constant; must be initialised exactly once (at declaration, or — for a field — in every constructor)
  • convention: static final int MAX_SIZE = 10; → UPPER_SNAKE_CASE
  • final method → can't be overridden · final class → can't be extended (both in Ch 03)
final with primitives vs references
final int bonus = 2;
bonus = 3;                          // ✗ compile error

final A kunal = new A("Kunal Kushwaha");
kunal.name = "other name";          // ✓ allowed — the OBJECT changes
kunal = new A("new object");        // ✗ compile error — the ARROW is fixed
     final A kunal
     ┌───────┐  arrow is welded  ┌─────────────────────┐
     │   ●───┼─────────────────→ │ name = "other name" │ ← contents
     └───────┘   (can't move)    └─────────────────────┘   CAN change
         ✗ ─ ─ ─→  new A("new object")
🎯 INTERVIEW TRAP

A final reference ≠ an immutable object. final freezes the arrow, not the object. Immutability (like String) must be designed into the class: private final fields, no setters.

"Must a final field be given a value right away?"

No — a blank final may be assigned later, but exactly once on every path of every constructor:

final int VALUE; Parent(int age) { VALUE = 32456789; } ✓

Ch 01 · Garbage collection

✦ GARBAGE COLLECTION ✦

🧠 IDEA

An object that no reference can reach is useless. The JVM's Garbage Collector (GC) finds such objects and frees their memory automatically — no free() / delete like C/C++.

you can't delete objects in Java — you just let go of them

🌍 IN REAL LIFE

Food-court trays: once you walk away from your table, staff clear the tray. You don't clean it yourself — and you don't decide when they come.

Java
A obj = new A("first");
obj = new A("second");    // "first" has no reference left → eligible for GC
   BEFORE                        AFTER   obj = new A("second")

   obj ──→ ┌─────────┐           obj ─┐    ┌─────────┐
           │ "first" │                │    │ "first" │ ← unreachable
           └─────────┘                │    └─────────┘   = garbage ✗
                                      └──→ ┌──────────┐
                                           │ "second" │
                                           └──────────┘

4 ways an object becomes eligible

  1. its reference is re-assigned (above)
  2. its reference is set to null
  3. the method holding the only reference finishes (local goes out of scope)
  4. "island of isolation" — objects pointing only at each other, nothing outside points at them
☕ JAVA REALITY
  • System.gc() is only a request; the JVM may ignore it.
  • Old code overrides finalize() (e.g. to print "Object is destroyed"). It is deprecated (since Java 9, for removal since Java 18): it may run late or never. For cleanup use close() / try-with-resources.
🎯 INTERVIEW TRAP

✦ PACKAGES ✦

🧠 IDEA

A package is a folder + a namespace for classes. It groups related classes and lets two classes share a name without clashing.

🌍 IN REAL LIFE

Two students called Rahul in one school → "Rahul of 10-A" and "Rahul of 12-C". The section is the package. Same idea as two files called notes.txt in different folders.

❓ WHY DO WE NEED IT?

  • our example has two classes named Greeting — one in package a, one in b — no clash
  • big projects stay organised (model, service, util …)
  • a package is also a visibility boundary (default access → Ch 04)
📖 DEFINITION

A package is a namespace that groups related classes and interfaces. It is both a naming and a visibility-control mechanism. The folder structure must mirror the package name.

✍️ SYNTAX

src/com/kunal/packages/a/Greeting.java
package com.kunal.packages.a;                          // ① FIRST statement

import static com.kunal.packages.b.Message.message;    // ② imports

public class Greeting {                                // ③ the class
    public static void main(String[] args) {
        System.out.println("Hello world");
        message();                     // static import → no class name
    }
}
   src/
    └── com/
         └── kunal/
              └── packages/
                   ├── a/
                   │    └── Greeting.java     ← package com.kunal.packages.a;
                   └── b/
                        ├── Greeting.java     ← package com.kunal.packages.b;
                        └── Message.java

📦 import — 4 flavours

  • import java.util.ArrayList; → one class
  • import java.util.*; → every class of java.util (but not its sub-packages)
  • import static java.lang.Math.*; → static members: sqrt(16) instead of Math.sqrt(16)
  • no import at all → write the fully qualified name: com.kunal.packages.b.Greeting g = new com.kunal.packages.b.Greeting();

java.lang (String, System, Math, Integer, Object …) is imported automatically.

⭐ JAVA RULE
  • at most one package statement, and it comes first
  • at most one public top-level class per file — and the file must be named after it
  • order in a file: package → imports → classes
🎯 INTERVIEW TRAP

import java.util.*; does not give you java.util.function.Consumer. A sub-package is a completely separate package — the dots only look like a hierarchy.

☕ JAVA REALITY

Same simple name from two packages (java.util.Date and java.sql.Date)? Import one, write the other's fully qualified name. The JVM finds packages via the current directory, the CLASSPATH variable, or -classpath / -cp.

✦ STATIC ✦

❓ WHY? — the problem

Human has age, name, salary … and population. Age belongs to one person. Population belongs to all humans together. As an instance field, every object would hold its own copy: kunal says 1, rahul says 1, arpit says 1 ✗.

🧠 IDEA

A static member belongs to the class, not to any object. One copy, shared by everyone, usable even before any object exists.

static ≈ ours
instance ≈ mine

🌍 IN REAL LIFE

A classroom: every student has their own notebook (instance), but there is one whiteboard (static). Write on the whiteboard → everyone sees the change.

💻 EXAMPLE

Main.java
public class Main {
    public static void main(String[] args) {
        Human kunal = new Human(22, "Kunal");
        Human rahul = new Human(34, "Rahul");
        Human arpit = new Human(34, "Arpit");

        System.out.println(Human.population);   // ClassName.member ✓
    }
}

class Human {
    int age;
    String name;
    static long population;            // ONE copy for the whole class

    Human(int age, String name) {
        this.age = age;
        this.name = name;
        Human.population += 1;      // every object bumps ONE counter
    }
}

❓ WHY can't static touch instance members directly?

An instance member belongs to some object. A static method runs with no object at all — there is no this. So "greeting()" inside a static method means greeting of … whom?

        greeting();            // ✓ means this.greeting()

    void greeting() {

  • static members are created when the class loads; instance members when an object is created

✦ INNER CLASSES ✦

🧠 IDEA

A class declared inside another class. Two kinds matter:

  • inner class (non-static) → every inner object is tied to one outer object
  • static nested class → just filed inside the outer class; needs no outer object

🌍 IN REAL LIFE

Inner class = a room: it can't exist without its house, and it sees everything in that house. Static nested class = a spare blueprint kept in the house's folder — filed under "House", but you can use it with no house built at all.

Main.java
public class Main {
    public static void main(String[] args) {
        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner();      // needs an Outer object
        inner.show();

        Outer.Nested nested = new Outer.Nested();  // no Outer needed
        nested.show();
    }
}

class Outer {
    private int x = 10;
    static int y = 20;

    class Inner {                    // non-static → tied to one Outer
        void show() {
            System.out.println("Inner sees x = " + x + ", y = " + y);
        }
    }

    static class Nested {            // static → belongs to the class Outer
        void show() {
            System.out.println("Nested sees y = " + y);
        }
        // using x here ✗ — which Outer's x? there is no Outer object
    }
}

Ch 02 · Singleton

✦ SINGLETON CLASS ✦

❓ WHY?

Some things must exist only once: app configuration, a logger, a connection pool. Many copies → wasted resources and conflicting state.

🌍 IN REAL LIFE

A country has one President at a time. Everyone asking "who is the President?" gets the same person.

🧠 IDEA — 3 ingredients

  1. private constructor → nobody outside can write new
  2. a private static field holding the instance
  3. a public static method → the only door in
Main.java
public class Main {
    public static void main(String[] args) {
        Singleton obj1 = Singleton.getInstance();
        Singleton obj2 = Singleton.getInstance();
        Singleton obj3 = Singleton.getInstance();
        System.out.println(obj1 == obj2 && obj2 == obj3);
        // new Singleton();   ✗ Singleton() has private access
    }
}

class Singleton {
    private static Singleton instance;      // the ONE object

    private Singleton() { }                 // ① no outside new

    public static Singleton getInstance() { // ② the only door
        if (instance == null) {             // ③ first call only (lazy)
            instance = new Singleton();
        }
        return instance;
    }
}
▶ Output
true
   obj1 ───┐
   obj2 ───┼────→  ┌───────────────────────┐
   obj3 ───┘       │  the ONE Singleton    │

"Why must getInstance() be static?"

Because before the first call no object exists — and you can't call an instance method without an object. Static is the only way in.

☕ JAVA REALITY

This lazy version is not thread-safe — two threads may both see null and create two objects. Real code uses an eager private static final instance, a synchronized/double-checked getInstance(), or simply enum Config { INSTANCE } (also safe against reflection & serialization).

Ch 03 · Inheritance

✦ INHERITANCE ✦

❓ WHY? — the problem

We have Box with l, h, w. Now we need BoxWeight (+ weight) and BoxPrice (+ cost). Copy-paste l, h, w and the constructors into each? Fix a bug → fix it 3 times ✗.

🧠 IDEA

A child class gets all the (non-private) members of a parent class and adds only what's new. Relationship: IS-A — a BoxWeight is a Box.

🌍 IN REAL LIFE

A child inherits common traits from the parents (surname, eye colour) and adds their own (their skills).

📖 DEFINITION

Inheritance — a mechanism where one class (subclass / child / derived) acquires the properties and behaviour of another (superclass / parent / base) using extends.

💻 EXAMPLE — the Box family

Main.java
public class Main {
    public static void main(String[] args) {
        BoxWeight box = new BoxWeight(2, 3, 4, 8);
        System.out.println(box.h + " " + box.w + " " + box.weight
                           + " " + box.getL());
    }
}

class Box {
    private double l;           // private → only Box's code can touch
    double h, w;

    Box(double l, double h, double w) {
        System.out.println("Box class constructor");
        this.l = l;
        this.h = h;
        this.w = w;
    }

    public double getL() { return l; }
}

class BoxWeight extends Box {       // BoxWeight IS-A Box
    double weight;                  // only the NEW stuff

    BoxWeight(double l, double h, double w, double weight) {
        super(l, h, w);             // let the parent set up its own part
        this.weight = weight;
    }
}

  • private members are not accessible in the child (they still exist inside the object)

✦ METHOD OVERRIDING ✦ (runtime)

🌍 IN REAL LIFE

A child inherits "cook dinner" from the parent but redefines how — same task name, new way of doing it.

         Parent      void area()   "I am in shapes"
            │
            ↓  same method signature
         Child       void area()   "pi * r * r"
            │
            ↓
    new implementation REPLACES the inherited one

💻 EXAMPLE — Shapes

Main.java
public class Main {
    public static void main(String[] args) {
        Shapes shape  = new Shapes();
        Shapes circle = new Circle();
        Shapes square = new Square();

        circle.area();
        square.area();

class Shapes {
    void area() { System.out.println("I am in shapes"); }
}

    @Override                  // "compiler, check that I really override"

⭐ JAVA RULE
  1. same name + same parameter list (else it's overloading!)
  2. return type: same, or a subtype (covariant return — Box copy() → BoxWeight copy() ✓)
  3. access: same or wider — public → protected ✗ ("attempting to assign weaker access privileges")
  4. can't override: final · static (hidden) · private (not inherited) · constructors
  5. may not throw new or broader checked exceptions

🧠 How does Java decide which area() runs?

   Shapes circle = new Circle();
   circle.area();

   COMPILER  →  "does type Shapes have area()?"   ✓ → call allowed
   JVM       →  "what is the OBJECT really?"       Circle
             →  run Circle.area()
                (not in Circle? → look in Shapes → then Object)

This runtime lookup is dynamic method dispatch — how Java implements runtime polymorphism.

⚠️ COMMON MISTAKE

Forgetting @Override and typing void Area() or void area(int r) → you silently created a new method; the parent's still runs. @Override turns that bug into a compile error.

class Student {

    private int marks;
      ↑ private → protect the internal state

                 ↑ setter → the ONLY way in, and it validates
        if (marks >= 0 && marks <= 100) {
            this.marks = marks;
        }
    }

    public int getMarks() {
                ↑ getter → controlled read
        return marks;
    }
}
Main.java — trying to cheat

        System.out.println(s.getMarks());

}

class Student {

    public void setMarks(int marks) {

    public int getMarks() { return marks; }
}

  • debugging: data changes through one door — put a breakpoint there

Data hiding — keeping fields private so they can't be accessed directly. It is the main tool of encapsulation; encapsulation is the bigger idea: bundling data with the methods that guard it.

✦ THE protected NUANCE ✦

🟠 HIGHLY IMPORTANT

🧠 IDEA

In another package, a subclass can use a protected member only through inheritance — on itself (or objects of its own type / its subtypes). It can not poke at the protected members of an arbitrary parent object.

one/Base.java
package one;

public class Base {
    protected void display() { System.out.println("in Base"); }
}
two/Derived.java
package two;
import one.Base;

public class Derived extends Base {
    void test(Base b, Derived d) {
        display();                // ✓ inherited — called on this
        d.display();              // ✓ a Derived reference
        new Derived().display();  // ✓ a Derived object
        b.display();              // ✗ has protected access in Base
        new Base().display();     // ✗ has protected access in Base
    }
}

✦ equals() + hashCode() ✦

🧠 IDEA — how a HashSet thinks

       │

   ┌───────┬───────┬───────┬───────┬───────┐

💻 EXAMPLE — doing it right

Main.java
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        Set<Student> set = new HashSet<>();
        set.add(new Student(15, "Kunal"));
        set.add(new Student(15, "Kunal"));   // the "same" student again
        System.out.println(set.size());
        System.out.println(new Student(15, "Kunal"));
    }
}

class Student {
    private final int rno;
    private final String name;

    Student(int rno, String name) { this.rno = rno; this.name = name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                    // same object
        if (!(o instanceof Student)) return false;     // null / other type
        Student other = (Student) o;
        return rno == other.rno && Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(rno, name);         // SAME fields as equals
    }

    @Override
    public String toString() {
        return "Student{rno=" + rno + ", name=" + name + "}";
    }
}

⭐ JAVA RULE

The contract 1. a.equals(b) is true → a.hashCode() == b.hashCode() must be true 2. same hash code does not mean equal (collisions are allowed) 3. equals must be reflexive, symmetric, transitive, consistent — and x.equals(null) is false 4. override both or neither, using the same fields

🎯 INTERVIEW TRAP

Override equals() without hashCode() → it compiles, it runs, and it silently breaks every HashSet/HashMap: contains() says false for an "equal" object, duplicates appear.

Ch 05 · Abstract classes

✦ ABSTRACT CLASSES ✦

🧠 IDEA

An abstract class is an incomplete class. It may declare abstract methods — methods with no body — that every concrete child must implement.

🌍 IN REAL LIFE

A parent says: "Every child of mine must choose a career and a partner — but I won't decide for them." The rule is fixed; the details are each child's responsibility.

📖 DEFINITION
  • abstract method — declared without a body: abstract void career(); — "subclass responsibility"
  • abstract class — declared with abstract; can't be instantiated; may mix abstract and concrete methods

💻 EXAMPLE

Main.java
public class Main {
    public static void main(String[] args) {
        Son son = new Son(30);
        son.career();
        son.normal();

        Parent daughter = new Daughter(28);  // abstract type as ref ✓
        daughter.career();

        Parent.hello();                       // static method ✓
        // Parent mom = new Parent(45);       ✗ Parent is abstract
    }
}

abstract class Parent {
    int age;
    final int VALUE;

    Parent(int age) {                // constructor ✓ (runs via super)
        this.age = age;
        VALUE = 32456789;
    }

    static void hello() { System.out.println("hey"); }
    void normal() { System.out.println("this is a normal method"); }

    abstract void career();                   // no body → child decides
    abstract void partner();
}

class Son extends Parent {
    Son(int age) { super(age); }
    @Override
    void career()  { System.out.println("I am going to be a doctor"); }
    @Override
    void partner() { System.out.println("I love Pepper Potts"); }
}

class Daughter extends Parent {
    Daughter(int age) { super(age); }
    @Override
    void career()  { System.out.println("I am going to be a coder"); }
    @Override
    void partner() { System.out.println("I love Iron Man"); }
}

❓ Why can't we write new Parent(45)?

It's incomplete — mom.career() would have no code to run. The compiler refuses: "Parent is abstract; cannot be instantiated".

"No objects… so why does an abstract class have a constructor?"

new Son(30) builds one object that contains a Parent part. super(age) runs Parent's constructor to initialise that part (age, VALUE). A constructor initialises; only new creates.

✦ ABSTRACT CLASS — THE RULES ✦

inside an abstract class … allowed?
abstract methods (zero or more) ✓
concrete methods, final methods ✓
constructors ✓ — run through super(...)
instance, static and final fields ✓

abstract final class ✗ illegal combination of modifiers

❓ Why no abstract static?

A static method is called on the class: Parent.career(). If it were abstract there'd be an empty method to call — and static methods can't be overridden, so no child could ever fill it in.

Ch 05 · Interfaces

✦ INTERFACES ✦

🧠 IDEA

An interface is a contract: it lists what a class must be able to do, never how. A class signs it with implements.

abstract class = IS-A
interface = CAN-DO

🌍 IN REAL LIFE

A power socket: any appliance with the right plug works — the socket doesn't care if it's a phone charger or a kettle. Or a job description: "every Driver must start(), stop(), brake()" — each driver does it their own way.

📖 DEFINITION

An interface is a reference type containing abstract method signatures (plus, since Java 8, default and static methods) and constants. A class can implement any number of interfaces.

✍️ SYNTAX — what Java adds silently

Java
interface Engine {
    int PRICE = 78000;     // = public static final int PRICE = 78000;
    void start();          // = public abstract void start();
}

    @Override

⭐ JAVA RULE
  • implementing methods must be public — void start() { } → "attempting to assign weaker access privileges; was public"

  • no constructors, no instance fields → an interface holds no state
  • implement every abstract method, or the class must be abstract

❓ WHY default methods?

Add a method to an interface used by 1000 classes → all 1000 break. A default method ships with a body, so old classes keep compiling. (That's how forEach() was added to every collection.)

        new Main().fun();
        A.greeting();            // static → call via the INTERFACE name
        // Main.greeting();      ✗ static interface methods: not inherited
    }
}

⭐ JAVA RULE

Default-method conflicts 1. class wins — a method in the class (or its superclass) beats any interface default 2. more specific interface wins — B extends A, both define fun() → B's 3. two unrelated interfaces with the same default → compile error ("types A and B are incompatible") until you override it

❓ WHY? — the problem

Arrays are fixed size. int[] a = new int[3]; then a 4th item → ✗ ArrayIndexOutOfBoundsException. We want a list that just… grows.

   Fixed array        int[] a = new int[3];   a[3] = 9  ✗ out of bounds
        ↓
   Capacity problem   ┌───┬───┬───┐
        ↓             │ 1 │ 2 │ 3 │  full!
   Resize             └───┴───┴───┘
        ↓             make a new array, 2× the size
   Copy old items     ┌───┬───┬───┬───┬───┬───┐
        ↓             │ 1 │ 2 │ 3 │ 4 │   │   │  ← then add 4
   Custom ArrayList   └───┴───┴───┴───┴───┴───┘
                      add() hides all this → the list feels "infinite"

💻 EXAMPLE (compact version)

CustomArrayList.java
import java.util.Arrays;

public class CustomArrayList {
    private int[] data = new int[10];   // DEFAULT_SIZE = 10
    private int size = 0;               // item count AND next free index

    public void add(int num) {
        if (size == data.length) resize();   // full? grow first
        data[size++] = num;
    }

    private void resize() {             // private → hidden detail
        int[] temp = new int[data.length * 2];
        for (int i = 0; i < data.length; i++) {
            temp[i] = data[i];          // copy old items
        }
        data = temp;                    // old array → garbage
    }

    public int remove()       { return data[--size]; }   // last item
    public int get(int index) { return data[index]; }
    public int size()         { return size; }

    @Override
    public String toString() {
        return Arrays.toString(Arrays.copyOf(data, size))
               + " size=" + size + " capacity=" + data.length;
    }

    public static void main(String[] args) {
        CustomArrayList list = new CustomArrayList();
        for (int i = 0; i < 14; i++) list.add(2 * i);
        System.out.println(list);
    }
}

✦ COMPARING OBJECTS ✦

❓ WHY?

Arrays.sort(intArray) is obvious. Arrays.sort(students) — by marks? roll no? name? Java can't guess. Two ways to tell it:

  • Comparable — the class defines its own natural order (compareTo)
  • Comparator — an outside rule you pass in (compare), as many as you like

compareTo / compare return negative (this first) · 0 (equal) · positive (other first).

Main.java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        Student[] list = {
            new Student(12, 89.76f), new Student(5, 99.52f),
            new Student(2, 95.52f),  new Student(13, 77.52f)
        };
        Arrays.sort(list);              // natural order → compareTo (marks)
        System.out.println(Arrays.toString(list));

        // a Comparator as a lambda → roll-number order
        Arrays.sort(list, (a, b) -> Integer.compare(a.rollno, b.rollno));
        System.out.println(Arrays.toString(list));
    }
}

class Student implements Comparable<Student> {
    int rollno;
    float marks;

    Student(int rollno, float marks) {
        this.rollno = rollno;
        this.marks = marks;
    }

    @Override
    public int compareTo(Student o) {
        return Float.compare(this.marks, o.marks);   // <0 · 0 · >0
    }

    @Override
    public String toString() { return rollno + ":" + marks; }
}

✦ LAMBDA EXPRESSIONS ✦

🧠 IDEA

A lambda is a method without a name that you can store in a variable and pass around — behaviour as data.

   (parameters)  ->  expression              (a, b) -> a + b

   (parameters)  ->  {                       (a, b) -> {
                       statements;               int r = a - b;
                       return value;             return r;
                     }                         }
📖 DEFINITION

A lambda implements a functional interface — an interface with exactly one abstract method: Runnable, Comparator<T>, Consumer<T>, Function<T, R>, Predicate<T>, or your own. @FunctionalInterface makes the compiler check the "exactly one" rule.

💻 EXAMPLE — LambdaFunctions

LambdaFunctions.java
import java.util.ArrayList;
import java.util.function.Consumer;

public class LambdaFunctions {
    public static void main(String[] args) {
        ArrayList<Integer> arr = new ArrayList<>();
        for (int i = 0; i < 5; i++) arr.add(i + 1);

        Consumer<Integer> fun = item -> System.out.print(item * 2 + ",");
        arr.forEach(fun);                       // pass behaviour IN
        System.out.println();

        Operation sum  = (a, b) -> a + b;
        Operation prod = (a, b) -> a * b;
        Operation sub  = (a, b) -> {            // block body
            int result = a - b;
            return result;
        };

        LambdaFunctions calc = new LambdaFunctions();
        System.out.println(calc.operate(5, 3, sum));
        System.out.println(calc.operate(5, 3, prod));
        System.out.println(calc.operate(5, 3, sub));
    }

    private int operate(int a, int b, Operation op) {
        return op.operation(a, b);
    }
}

@FunctionalInterface
interface Operation {
    int operation(int a, int b);      // exactly ONE abstract method
}

}

💻 EXAMPLE — deep copy

Main.java
import java.util.Arrays;

public class Main {
    public static void main(String[] args)
            throws CloneNotSupportedException {
        Human kunal = new Human(34, "Kunal Kushwaha");
        Human twin = (Human) kunal.clone();
        twin.arr[0] = 100;
        System.out.println(Arrays.toString(twin.arr));
        System.out.println(Arrays.toString(kunal.arr));   // untouched ✓
    }
}

class Human implements Cloneable {      // marker interface: "clone allowed"
    int age;
    String name;
    int[] arr = {3, 4, 5, 6, 9, 1};

    Human(int age, String name) { this.age = age; this.name = name; }

    @Override
    public Object clone() throws CloneNotSupportedException {
        Human twin = (Human) super.clone();   // shallow: fields as-is
        twin.arr = new int[this.arr.length];  // deep: twin's OWN array
        for (int i = 0; i < arr.length; i++) twin.arr[i] = this.arr[i];
        return twin;
    }
}
▶ Output
[100, 4, 5, 6, 9, 1]
[3, 4, 5, 6, 9, 1]

Keep only return super.clone(); → both lines print [100, 4, 5, 6, 9, 1].

⭐ JAVA RULE
  • the class must implements Cloneable (a marker interface — no methods) or super.clone() throws CloneNotSupportedException
  • Object.clone() is protected → override it as public to call it from outside
  • super.clone() builds the copy without running any constructor
☕ JAVA REALITY

Many Java experts avoid Cloneable (awkward design: checked exception, casts, shallow by default). A copy constructor — new Human(kunal) — is often clearer. Sharing a String field is fine: strings are immutable.

🟢 FUNDAMENTALS

What is OOP? Name its four pillars.

A way of organising programs around objects that bundle data and behaviour. Pillars: inheritance, polymorphism, encapsulation, abstraction.

Class vs object?

A class is the blueprint (logical, written once). An object is an instance created at runtime with new; it occupies heap memory and has its own state.

What exactly does new do?

Allocates memory for the object on the heap at runtime, initialises fields (defaults → initialisers → constructor) and returns a reference to it.

What is a constructor, and how is it different from a method?

A block that initialises a new object: same name as the class, no return type, runs automatically once per new, is never inherited and can't be static/final/abstract.

When does Java give you a default constructor?

Only when the class declares no constructor at all. Write any constructor and the no-arg one disappears.

What is this?

A reference to the current object. Uses: this.field (vs a parameter), this(...) (constructor chaining), passing or returning the current object.

What is a static variable?

A class-level variable: one shared copy, created when the class loads, accessed as ClassName.var (e.g. Human.population).

What is a package and why use one?

A namespace + folder for related classes. It prevents name clashes (two Greeting classes), organises code and acts as an access boundary.

What is inheritance? Which keyword?

A child class acquiring a parent's members with extends — an IS-A relationship (BoxWeight is a Box).

What is method overloading?

Same method name, different parameter lists (number / type / order). The compiler picks the version → compile-time polymorphism.

What is method overriding?

A subclass redefining an inherited instance method with the same signature. The JVM picks the version from the object's type → runtime polymorphism.

What is encapsulation?

Bundling data with the methods that operate on it and controlling access — private fields reached only through validating methods.

What is abstraction?

Exposing only what an object does while hiding how — via simple public methods, abstract classes and interfaces.

Name Java's access modifiers from most to least restrictive.

private → default (package-private) → protected → public.

What is an interface?

A contract of methods a class promises to implement. Methods are implicitly public abstract (plus default/static/private with bodies), fields are public static final; a class can implement many.

🟡 INTERMEDIATE

Why can't a static method use instance variables directly?

Instance variables belong to an object, and a static method runs with no current object (this doesn't exist). Use a reference: obj.field.

What does super() do, and where must it be?

Calls the parent's constructor; it must be the first statement. If you write neither this(...) nor super(...), the compiler inserts super().

In what order do constructors run in A ← B ← C when you write new C()?

Calls climb up to Object, bodies finish top-down: Object → A → B → C. The parent part must be ready before the child's.

What is dynamic method dispatch?

Resolving a call to an overridden method at runtime from the actual object's class — the mechanism behind runtime polymorphism.

List the rules for a valid override.

Same name & parameters; same or covariant return type; same or wider access; no new or broader checked exceptions; the parent method must not be final, static or private.

Can you overload main()?

Yes — but the launcher calls only the entry-point form (public static void main(String[] args); Java 25 also accepts instance main). Other overloads are ordinary methods.

What is a static block and when does it run?

Code that runs once when the class is initialised (first use) — for the main class, before main() starts. Used for complex static initialisation.

Inner class vs static nested class?

Inner (non-static) objects are tied to an outer object — created as outer.new Inner() — and can use its instance members. Static nested classes need no outer object — new Outer.Nested() — and see only static outer members directly.

How do you write a singleton?

private constructor + private static instance + public static getInstance(). Make it thread-safe with eager init, synchronisation, or simply enum Singleton { INSTANCE }.

What does final mean on a variable, a method and a class?

Variable → assigned once. Method → can't be overridden. Class → can't be extended (String, wrapper classes).

Can an abstract class have a constructor? Can you instantiate it?

It can have constructors (run via super(...) to set up the parent part), but new AbstractClass() is a compile error.

Abstract class vs interface — the two differences that matter most?

(1) An abstract class can hold state and constructors; an interface can't. (2) A class extends one class but implements many interfaces.

What are default methods and why were they added?

Interface methods with a body (Java 8). They let interfaces gain new methods without breaking every class that already implements them (e.g. forEach).

A class implements two interfaces that both have default void hi(). What happens?

Compile error ("types … are incompatible") until the class overrides hi(); inside it may call A.super.hi().

Why must hashCode() be overridden together with equals()?

The contract says equal objects must have equal hash codes. HashSet/HashMap find the bucket by hashCode() first — break it and lookups miss, duplicates appear.

== vs equals() for Strings?

== checks whether both references point to the same object; equals() compares the characters. Always use equals() for content.

What are generics, and what do they buy you?

Type parameters (List<T>) — compile-time type safety, no casts, one reusable implementation for all types.

What is type erasure?

The compiler removes generic type information after checking it; at runtime T becomes Object (or its bound). Hence no new T[], no instanceof T.

Checked vs unchecked exceptions?

Checked (subclasses of Exception, not RuntimeException) must be caught or declared with throws. Unchecked (RuntimeException, Error) aren't enforced by the compiler.

Shallow vs deep copy?

Shallow copies each field's value — nested objects are shared. Deep copy also duplicates the nested mutable objects so the copies are fully independent.

Interview bank · Tricky

🔴 TRICKY

Can we override a static method?

No. A same-signature static method in the child hides the parent's; calls are resolved from the reference type at compile time, and @Override on it is a compile error.

Can we override a private method?

No — private methods aren't inherited. A same-named method in the child is a brand-new, unrelated method.

Can a constructor be final, static or abstract?

None of them — compile error. Constructors aren't inherited (so final/abstract are meaningless) and they initialise an instance (so static makes no sense).

Is Java pass-by-reference for objects?

No — Java is always pass-by-value. For objects the value copied is the reference: you can mutate the shared object, but re-pointing the parameter never affects the caller (the swap(Integer, Integer) puzzle).

final StringBuilder sb = new StringBuilder("a"); sb.append("b"); — legal?

✓ Legal. final freezes the reference, not the object; only sb = new StringBuilder() would fail.

Human h = null; h.population where population is static — NullPointerException?

No — it prints the value. Static access is bound to the reference's type at compile time; the null object is never touched.

A parent constructor calls a method that the child overrides. Which version runs, and what does it see?

The child's version (dynamic dispatch works even during construction) — but the child's fields aren't initialised yet, so it sees default values (0, null). See Q61.

Can an interface have a constructor or instance fields?

No. Interfaces have no state: fields are implicitly public static final constants, and constructors are not allowed.

Can an abstract class be final?

No — "illegal combination of modifiers": abstract needs a subclass, final forbids one.

Does import java.util.*; import java.util.function.Function?

No. Sub-packages are separate packages; a wildcard import covers one package only.

Can a top-level class be private or static?

Neither. Top-level classes are public or package-private; static applies only to nested classes.

Overloads f(long), f(Integer), f(Object) — which one does f(5) call?

f(long). Resolution order: exact/widening primitive first, then boxing, then varargs. (f('a') also picks long.) See Q59.

Can you new an enum? Can an enum extend a class?

No and no. Constants are created by the JVM; every enum already extends java.lang.Enum. It can implement interfaces.

What does try { return 1; } finally { return 2; } return?

2 — a return in finally overrides the earlier one (and would even swallow an exception). Never return from finally.

try { return x; } finally { x = 2; } with int x = 1 — returned value?

1. The return value is evaluated and saved before finally runs; changing the local afterwards doesn't affect it. See Q65.

Is List<String> a subtype of List<Object>?

No — generics are invariant. Otherwise you could add an Integer through the List<Object> view. Use List<?> / List<? extends Object>.

Does super.clone() call a constructor?

No. Object.clone() allocates a field-by-field copy without running any constructor (and throws CloneNotSupportedException unless the class implements Cloneable).

Can a class be abstract without any abstract method?

Yes — it simply can't be instantiated. (The reverse isn't allowed: an abstract method forces the class to be abstract.)

Inside two.Derived extends one.Base, does new Base().display() compile if display() is protected?

No. Outside the package, protected members are reachable only through inheritance — on this or references of type Derived (or its subtypes).

System.out.println(null); — what does it print?

Nothing — it doesn't compile: "reference to println is ambiguous" (println(char[]) vs println(String)).

🧠 CONCEPTUAL

Why does Java forbid multiple inheritance of classes but allow many interfaces?

Two parent classes can bring conflicting code and duplicate state (the diamond problem) plus two constructor chains. Interfaces carry no state, and conflicting defaults must be resolved explicitly — so many interfaces are safe.

Why is main() static?

At startup no object exists; static lets the JVM call main on the class itself without guessing how to construct one. (Java 25's launcher can also create the object for an instance main, but the classic answer stands.)

Why aren't constructors inherited?

A constructor initialises its own class's part of the object. A parent's constructor knows nothing about the child's fields, so inheriting it would create half-initialised objects. Children reuse it explicitly through super(...).

Why is composition often preferred over inheritance?

HAS-A relationships can be swapped at runtime (NiceCar.upgradeEngine()), don't lock you into one parent, and don't break when a base class changes (the fragile base class problem). Use inheritance for true IS-A families.

When would you choose an abstract class over an interface?

When related classes share state and code (fields, constructors, protected helpers) and form a genuine family. Choose an interface for a capability that unrelated classes can implement.

Compile-time type vs runtime type — why does the difference matter?

The compile-time (reference) type decides what you may call; the runtime (object) type decides which overridden method runs. Every polymorphism question is really this sentence.

Why keep fields private even if the getter and setter do nothing special?

Freedom to change later: add validation, make the field read-only, compute it, log changes — without touching any caller. Public fields freeze your design forever.

How does a HashMap find a key?

hashCode() picks the bucket; equals() finds the exact key inside it. That's why the two must agree (Ch 04).

Why are Strings immutable (and the class final)?

Safe sharing in the string pool, cacheable hash codes for map keys, thread safety, and security (file paths, class names can't be altered after checks). final stops subclasses from breaking those guarantees.

What do generics solve that an Object-based container can't?

With Object the compiler can't stop wrong types going in, and every read needs a cast that may fail at runtime. Generics move those errors to compile time and remove the casts.

Conceptually, why can't static methods be overridden?

Overriding means "decide at runtime from the object". A static method has no object — it's bound to the class at compile time — so there is nothing to dispatch on.

When should you create a custom exception — checked or unchecked?

When a domain-specific failure deserves its own name (InsufficientBalanceException). Checked if the caller can reasonably recover and must be forced to think about it; unchecked for programming errors.

Why is Vector considered legacy?

It predates the Collections Framework and synchronises every call — a cost most code doesn't need, and it still doesn't make compound actions safe. ArrayList + targeted concurrency tools are better.

Why are enums better than int or String constants?

Type safety (only valid values compile), a namespace, usable in switch, can carry fields and methods, built-in values()/valueOf(), and == comparison is safe.

How do the four pillars cooperate in one design — say, payments?

An interface PaymentMethod (abstraction) implemented by Card, Upi, Wallet (inheritance of type); checkout(PaymentMethod p) calls p.pay() (polymorphism); each class keeps balances and PINs private behind validated methods (encapsulation).

⭐ 20 golden Java rules

  1. A reference is not the object — b = a copies only the arrow.
  2. Java is always pass-by-value; for objects, the reference is copied.
  3. Write any constructor and the free default one disappears.
  4. this(...)/super(...) come first; super() is added if you write neither.
  5. Constructors are never inherited — so never overridden.
  6. Static = one copy per class; a static context has no this.
  7. Static methods are hidden, not overridden; fields are never polymorphic.
  8. Reference type → what you may call; object type → which override runs.
  9. Overloading needs different parameters — return type alone isn't enough.
  10. Overriding keeps the signature and can't reduce access.
  11. final freezes the variable, not the object it points to.
  12. One parent class, many interfaces.
  13. Interface fields are public static final; its methods are public.
  14. Abstract classes can't be instantiated but do have constructors.
  15. protected outside the package works only through inheritance.
  16. Override equals() → override hashCode() with the same fields.
  17. Compare objects with .equals(); == checks identity.
  18. Generics are invariant and object-only: List<Integer> ≠ List<Number>, List<int> ✗.
  19. Catch specific → general; finally always runs (never return from it).
  20. Map is not a Collection; enums can't extend or be extended.
